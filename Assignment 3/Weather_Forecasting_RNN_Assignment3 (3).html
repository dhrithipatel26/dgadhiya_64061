Assignment 3: Weather Forecasting with Deep Learning¶

Introduction¶

Weather conditions change over time, making temperature forecasting an interesting problem for deep learning. In this assignment, I will explore how recurrent neural networks can learn patterns from historical weather measurements and use them to predict future temperatures.

My main goal is to compare different neural network architectures and understand how their design affects forecasting performance. I will experiment with GRU, LSTM, and convolutional-recurrent models using the Jena climate dataset.

To make the comparison meaningful, I will evaluate the models using Mean Absolute Error (MAE), apply early stopping during training, and compare their validation results. The strongest models will then be evaluated on the test dataset.

By comparing the results, I hope to identify which architecture provides more accurate temperature predictions and whether additional model complexity improves performance.

Data Preparation and Interpretation¶

I divided the weather dataset into training, validation, and testing portions while keeping the observations in their original time order. This is important because weather forecasting depends on past measurements, and mixing future observations into the training data could make the evaluation misleading.

I also standardized the numerical features using the mean and standard deviation calculated from the training data. I then applied those same values to the validation and testing sets to keep the preprocessing consistent and avoid using future information during normalization.

# Step 6 | Preparing historical weather sequences

# Use one observation every hour (6 original readings)
weather_hourly_step = 6

# Five days of hourly observations
weather_history_hours = 120

# Forecast temperature 24 hours after the final input
weather_forecast_hours = 24

# Identify the temperature feature
weather_temperature_index = (
    weather_features.columns.get_loc("T (degC)")
)

# Convert normalized datasets to NumPy arrays
weather_train_array = weather_training_scaled.to_numpy(
    dtype="float32"
)

weather_val_array = weather_validation_scaled.to_numpy(
    dtype="float32"
)

weather_test_array = weather_testing_scaled.to_numpy(
    dtype="float32"
)

# Create sequences without crossing dataset boundaries
def build_weather_windows(weather_array):
    weather_hourly = weather_array[::weather_hourly_step]

    weather_inputs = []
    weather_targets = []

    final_start = (
        len(weather_hourly)
        - weather_history_hours
        - weather_forecast_hours
        + 1
    )

    for window_start in range(final_start):
        window_end = window_start + weather_history_hours

        weather_inputs.append(
            weather_hourly[window_start:window_end]
        )

        weather_targets.append(
            weather_hourly[
                window_end + weather_forecast_hours - 1,
                weather_temperature_index
            ]
        )

    return (
        np.asarray(weather_inputs, dtype="float32"),
        np.asarray(weather_targets, dtype="float32")
    )

# Prepare training, validation, and testing sequences
weather_train_x, weather_train_y = build_weather_windows(
    weather_train_array
)

weather_val_x, weather_val_y = build_weather_windows(
    weather_val_array
)

weather_test_x, weather_test_y = build_weather_windows(

)

Preparing Time-Series Inputs¶

I converted the weather measurements into hourly observations to reduce the amount of data processed during training. For each prediction, I used five days of historical weather conditions as input and selected the temperature 24 hours after the final input measurement as the target.

I created the training, validation, and testing sequences separately so that no input window crosses between the datasets. This gives each model the same forecasting task and allows me to compare their performance fairly.

GRU Model Interpretation¶

I started with a GRU-based neural network to establish an initial forecasting model. The GRU layer uses historical weather observations to learn patterns that may help predict future temperatures. I also included dropout to reduce overfitting.

During training, I monitored validation Mean Absolute Error (MAE) and applied early stopping with a patience of five epochs. This allowed training to stop when the model was no longer improving on the validation data, while restoring the weights from its best-performing epoch.

I will use the GRU model's validation MAE as a reference when comparing it with the other architectures.

GRU Training Performance Interpretation¶

The GRU model showed steady improvement during training. Its validation MAE decreased from 0.2913 in the first epoch to its lowest value of 0.2704 at epoch 10.

Although the training error continued to decrease, the validation error did not improve after epoch 10. This suggests that additional training was no longer providing a meaningful improvement on unseen validation data.

Early stopping ended the training process after 15 epochs and restored the model weights from epoch 10. This helped avoid unnecessary training while preserving the best validation performance.

The GRU model provides an initial benchmark for comparing the other forecasting architectures.

I included dropout to help reduce overfitting and used early stopping to monitor validation MAE. I kept the same training and validation datasets as the earlier experiments so that the results could be compared consistently.

This experiment allows me to evaluate whether combining convolutional and recurrent layers provides an advantage over using recurrent layers alone.
